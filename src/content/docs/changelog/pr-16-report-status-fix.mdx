## docs: fix report status terminology (Ready -> Sent)

## What changed

The daily reports guide's status table and regenerate steps documented **Ready** as the terminal/completed status for a report. That's not what the product actually shows.

## Why

Verified directly against the live dev app (`dev.app.consequential.io`, tenant: thirdlove):

- The Reports list UI shows a `sent` badge on completed reports, not `Ready`.
- Confirmed via the raw API (`GET /api/v1/tenants/:tenantId/reports` and `.../reports/:date`) — the `status` field for a fully-generated report (e.g. `2026-07-24`, with populated `finalUri`) is literally `"sent"`. Across all 12 reports on this tenant, the only status values observed are `"failed"` and `"sent"` — `"ready"` never appears.

## Changes

- `## Report status` table: `**Ready**` -> `**Sent**`
- `## Regenerate a report` step 3: "Wait for the status to return to **Ready**" -> "**Sent**"

## Not changed (unverified, flagging for awareness)

Could not confirm `Generating` or `No baseline` against real data — those states weren't present in the sample pulled. Left as-is since there's no evidence they're wrong, but someone with backend access may want to double check the full status enum.

## How to verify

- `npm run build` in `consequential-docs/` — passes.
- Compare against a live tenant's Reports list / API response for the `status` field.
