This guide covers Cloudflare setup, token generation, and custom domains.

## Setup

### Prerequisite

If you are on the free Cloudflare plan, switch to a paid plan. Click **Plans** in the navigation menu.

### Worker

Enable Workers in Cloudflare first. If you already use Workers, skip this step.

<Steps>

1. Go to the **Workers & Pages** page and click **Create Worker**.
2. Click **Deploy**.
3. After you create the worker, click [Workers & Pages](https://dash.cloudflare.com/?to=/:account/workers-and-pages) in the navigation to go back to the workers page.

</Steps>

### Analytics Engine

On the [Workers & Pages page](https://dash.cloudflare.com/?to=/:account/workers-and-pages), enable Analytics Engine. This feature gives you insights about your usage.

<Steps>

1. Click **Set up** next to **Analytics Engine**.
2. Click **Enable Analytics Engine** to complete the setup.

</Steps>

### R2

Enable R2 to store data if you enable it in the dashboard. Click [R2](https://dash.cloudflare.com/?to=/:account/r2) in the navigation menu. If you don't have a credit card added yet, add it. Then click **add R2**.

### Queues

Enable Queues last. Click [Queues](https://dash.cloudflare.com/?to=/:account/workers/queues) in the navigation menu. In the popup, agree to the charge. Queues is then enabled.

## How to generate a Cloudflare token?

<Steps>

1. Go to the [API Tokens page](https://dash.cloudflare.com/profile/api-tokens) and click **Create token**.
2. Use the **Cloudflare Workers** template. The template provides most of the permissions you need.
3. Add the following permissions:
   - **Account: Account Analytics (read)** — shows charts of your usage.
   - **Zone: DNS (edit)** — creates the DNS record that links the worker with the domain.
   - **Account: D1 (edit)** — creates the database used for saving errors.
4. Click **Continue to summary** and click **Create Token**.

</Steps>

You now have a token to insert as part of host creation.

## Domains not hosted in Cloudflare

If your domain isn't hosted in Cloudflare but you want to use it in your Cloudflare account, select the **Custom hostname** option when adding a host in onboarding. This lets you use the Cloudflare custom hostname option to link your primary domain with your workers.

<Steps>

1. Enable the **Custom Hostnames** option in your Cloudflare account. Go to the [Custom Hostnames page](https://dash.cloudflare.com/?to=/:account/:zone/ssl-tls/custom-hostnames). If you haven't set it up yet, enable it, add payment info, and purchase it. The first 100 domains are free.
2. Add a fallback domain. Normally you set it as `fallback.somedomain.com`, where `somedomain.com` is your domain in Cloudflare.
3. Add an AAAA record for `fallback.somedomain.com` in your DNS with the value `100::`. This maps your fallback domain to your workers.
4. Update your existing API token to add two more permissions:
   - **Account: SSL and Certificates (edit)** — used for domain creations.
   - **Zone: Zone (read)** — used to check the fallback origin.

</Steps>
